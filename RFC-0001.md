# RFC-0001 — Heaven Core Decomposition

Status: Draft

Version: 0.1

Target: Heaven v0.2

Author: Aziz Abouchi

Date: 2026-07-01

---

# 1. Motivation

Heaven a atteint une taille suffisante pour nécessiter une séparation explicite entre :

* noyau symbolique
* moteur de preuves
* logique
* réécriture
* runtime distribué
* codegen
* compilation

Le dépôt contient actuellement :

147 modules Zig

≈ 28 400 LOC

Le module principal :

src/core/heaven_expr.zig

contient :

3473 LOC

et agit simultanément comme :

* façade utilisateur
* moteur symbolique
* CAS
* moteur de preuve
* moteur logique
* système de réécriture
* moteur de compétences
* générateur de code

Cette concentration de responsabilités ralentit :

* l'évolutivité
* les tests
* la compilation incrémentale
* la modularité
* le support WASM
* la distribution réseau

---

# 2. Objectifs

RFC-0001 introduit une architecture par sous-systèmes.

Objectifs :

* réduire heaven_expr.zig
* isoler les responsabilités
* rendre Heaven composable
* préparer HeavenSwarm
* préparer HeavenKernel
* préparer HeavenCloud

# 4. HeavenContext

```zig

    symbolic : SymbolicEngine,

    calculus : CalculusEngine,

    rewrite : RewriteEngine,

    logic : LogicEngine,

    proof : ProofEngine,
```

HeavenContext devient l'API principale.

# 13. Heaven

Heaven devient une façade.

Exemple :

```zig
pub fn simplify(
    self:*Heaven,
    src:[]const u8
)

{
    return self.ctx.symbolic.simplify(src);
}
```

```zig
pub fn query()

{
    return self.ctx.logic.query(...);
}
```

```zig
pub fn derive()

{
    return self.ctx.calculus.derive(...);
}
```
