Introduction

Heaven est un langage de programmation unifié qui fusionne les meilleures idées de :

  • Idris : types dépendants, preuves formelles intégrées
  • Erlang : acteurs, distribution, tolérance aux pannes
  • Haskell : pureté fonctionnelle, paresse

Vision

Heaven traite les mathématiques, la physique, la chimie, la musique, la philosophie comme des ontologies computationnelles interchangeables via un pivot commun : l'EGraph.

💡 Heaven n'est pas qu'un langage : c'est un intégrateur vertical du code vers la preuve certifiée.

Exemple

-- Un théorème avec sa preuve
theorem add_comm : ∀ a b : Nat, a + b = b + a
proof
  by induction on a
  case zero: auto
  case succ n: rewrite add_comm; auto

-- Distribution transparente
compute_on_cluster : List Nat -> Nat
compute_on_cluster xs =
  spawn worker1 (sum (take (length xs / 2) xs))
  + spawn worker2 (sum (drop (length xs / 2) xs))

Quick Start

💡 Le serveur HTTP écoute sur le port PORT + 2919. Si tu lances heaven 8080, ouvre http://127.0.0.1:10999/

1. Expressions simples

heaven> 2 + 3 * 4
    → 14

    heaven> let x = 10 in x * x
    → 100

2. Définir une fonction

-- Pas de mot-clé 'def', on écrit directement le nom
    fib zero = 0
    fib (succ zero) = 1
    fib (succ (succ n)) = fib (succ n) + fib n

    heaven> fib (succ (succ (succ (succ (succ (succ (succ (succ (succ (succ zero))))))))))
    → 55

3. Prouver un théorème

theorem sum_zero : forall (n : Nat). equal (n + 0) n
    proof by induction; auto

    [TEST] Théorème 'sum_zero' prouvé par induction.

4. Types de données

data Nat = zero | succ Nat
    data List a = nil | cons a (List a)

    add zero n = n
    add (succ n) m = succ (add n m)

5. Distribution

Ouvre plusieurs onglets sur http://127.0.0.1:10999/repl. Ils forment automatiquement un swarm P2P via BroadcastChannel et peuvent échanger des EGraphs.

Définitions de fonctions

Pas de mot-clé def. On écrit directement le nom et les patterns :

-- Pattern matching sur le premier argument
    add zero n = n
    add (succ n) m = succ (add n m)

    -- Multiplication
    mul zero n = zero
    mul (succ n) m = add m (mul n m)

    -- Fonction à plusieurs clauses
    factorial zero = succ zero
    factorial (succ n) = mul (succ n) (factorial n)

Types de données

data Nat = zero | succ Nat
    data List a = nil | cons a (List a)
    data Bool = true | false
    data Maybe a = none | some a

Théorèmes et preuves

-- Déclaration de théorème
    theorem add_comm : forall (n m : Nat). = (add n m) (add m n)

    -- Preuve par induction
    proof by induction on n; auto

    -- Théorème avec preuve inline
    theorem sum_zero : forall (n : Nat). = (n + 0) n
    proof by induction; auto

Type System

Heaven utilise un système de types dépendants inspiré d'Idris et du Calcul des Constructions Inductives.

Types de base

Nat     -- entiers naturels
Int     -- entiers relatifs
Float   -- flottants
Bool    -- booléens
String  -- chaînes
Sym     -- symboles (internés)

Types dépendants

-- Vecteur de taille connue
data Vec (n : Nat) (a : Type)
| vnil : Vec zero a
| vcons : a → Vec n a → Vec (succ n) a

-- Fonction dont le type de retour dépend de la valeur
head : Vec (succ n) a → a
head
| vcons x _ => x

Inférence

Le type-checker utilise l'EGraph pour unifier les types modulo les équations de réécriture. Cela permet des preuves d'égalité de types automatisées.

Proofs

Les preuves sont first-class dans Heaven : un théorème est une valeur, une preuve est un programme.

Structure d'une preuve

theorem name : proposition
proof
  tactic1
  tactic2
  ...

Tactiques disponibles

  • auto : résolution automatique basique
  • induction on x : induction structurelle
  • rewrite thm : réécriture par un théorème
  • simp : simplification par l'EGraph
  • trivial : cas triviaux

Exemple complet

theorem add_assoc : ∀ a b c, (a + b) + c = a + (b + c)
proof
  by induction on a
  case zero: simp
  case succ n:
    rewrite add_comm
    rewrite add_assoc
    auto

Actors & Distribution

Heaven intègre nativement le modèle d'acteurs d'Erlang pour la distribution.

Spawning

worker : Pid
  worker = spawn \self ->
      receive
      | (msg, from) -> send from (process msg); loop
      end

Communication

send pid message
receive
| pattern1 -> expr1
| pattern2 -> expr2
end

Swarm distribué

Chaque instance Heaven (native ou WASM) fait partie d'un swarm. Les EGraphs sont synchronisés via le protocole de messages suivant :

  • egraph_sync : fusion d'EGraphs
  • work_steal_request : vol de travail
  • proof_request : demande de preuve

EGraph

L'EGraph (Equality Graph) est la structure centrale de Heaven. Il représente des expressions modulo des équations de réécriture.

Concepts

  • E-Class : ensemble de nœuds considérés égaux
  • E-Node : nœud AST (littéral, symbole, application)
  • Union-Find : maintient les classes d'équivalence
  • Saturation : application des règles jusqu'au point fixe

API

egraph.addExpr(id)        // ajoute une expression
egraph.merge(a, b)        // fusionne deux classes
egraph.extract(class, qtt) // extrait la meilleure représentation
egraph.saturate(rules, budget) // sature avec budget temporel

Swarm Protocol

Le protocole de communication du swarm Heaven est basé sur des messages binaires TLV (Type-Length-Value).

Format

[peer_id: 16 bytes]
[msg_type: 1 byte]
[timestamp: 8 bytes]
[payload: N bytes]

Types de messages

Type Code Description
egraph_sync2Synchronisation d'EGraph
proof_request3Demande de preuve
proof_result4Résultat de preuve
work_steal_request5Demande de travail
work_steal_response6Réponse avec travail

WASM Runtime

Heaven compile vers WebAssembly pour s'exécuter dans le navigateur avec les mêmes capacités que la version native.

Exports WASM

wasm.init()                      // initialise le moteur
wasm.dispatch(cmd_len, arg_len)  // exécute une commande
wasm.getInputPtr()               // buffer d'entrée
wasm.getOutputPtr()              // buffer de sortie

// Swarm
wasm.init_swarm()                // initialise le swarm
wasm.tick_swarm()                // tick loop (60 FPS)
wasm.debug_egraph()              // debug

// Métriques
wasm.get_metrics_json()          // JSON des métriques
wasm.get_metrics_json_len()      // longueur

Platform Abstraction Layer

Tout le code métier est commun entre natif et WASM grâce à la PAL (src/platform/{native,wasm}.zig).
